# POCKETROLL 35 — the experience of shooting film, not just the look

A phone camera that behaves like a real 35mm camera. Only 36 exposures per roll; frames stay **latent** until you develop the whole roll in the darkroom; every developed roll auto-prints a **contact sheet** and lands in a dated **film archive**; opening the back door before developing fogs your frames. The look (color science per film stock, ISO-appropriate grain, halation, light leaks by stock) comes from the experience, not from presets. The UI is the **back of a point-and-shoot camera** (cream plastic body, chrome viewfinder bezel, red LED frame counter, DX film canister label, filmstrip); the engine emulates real camera × film combinations from the material library in `assets/`. Avoid being another VSCO/Lightroom — the product is the ritual.

## Run it
Live: **https://huckn1900.github.io/pocketroll/** (open on your phone — HTTPS secure context = camera works; installable as PWA)
```
python -m http.server 8765      # any static server works
open http://127.0.0.1:8765/
```
- It is a PWA: installable from Chrome on Android/desktop, works offline after first load (service worker caches the shell). Fonts are bundled OFL latin subsets (`assets/fonts/`: Roboto Condensed for brand/print, IBM Plex Mono for parameters) — no runtime webfont dependency.
- Controls: **SHUTTER** button or spacebar exposes a frame; **camera bag** / **film shelf** load gear (swapping cameras never resets the roll); **develop roll** runs the darkroom ritual (developer → stop bath → fixer → wash, then frames reveal and archive); **contact sheet ↓** downloads the lab proof sheet after developing; **scan in photo** lab-develops an external photo as a loose frame; **back door** opens the door — on an undeveloped roll this FOGS the exposed frames; tap the finder for the full LCD readout; tap a latent frame for a brief preview pulse only.
- Test hooks: `?cam=<id>&film=<id>&autoshot=1&dev=1&date=1&hud=full&page=roll|gallery|settings`; `test/calibration.html` (every stock in `assets/films.json` on a real photo, for parameter tuning); `sounds.html` (sound lab: film-advance lever/motor + focus chirp/whir variants for auditioning before integration); `test/features-check.mjs` / `test/export-check.mjs` / `test/pwa-check.mjs` / `test/backup-check.mjs` / `test/viewfinder-check.mjs` (every body's finder drawn against what its profile declares, marks aligned to the displayed picture, no leftover universal-interface markup) / `test/sound-smoke.mjs` / `test/page-probe.mjs` (CDP assertions & debug probes). The browser executable is configurable: set `DSH_CHROME` to any Chrome/Chromium build (`test/browser.mjs`); without it each suite uses the platform default.

## Architecture
- `assets/cameras.json` — **18 bodies** today (5 free: Olympus Trip 35, Instamatic, AF35M, Lomo LC-A, Nikon T4 · 13 Pro: premium compacts and rangefinders such as Contax T2, MJU-II, GR1v, TC-01, L35AF, plus medium-format bodies). Each carries a `camera_character` (color cast gains, vignette, sharpness, halation bias, quirks like LC-A light leaks / AF35M flash pop), and where it has one, a real `gate` aspect.
- `assets/films.json` — **28 stocks** today, each with its own parameters and its lab `process`: 5 free/current (HP5+, Portra 400, Gold 200, Velvia 50, ColorPlus), 21 Pro/current (Ektar, Vision3 500T, Cinestill 800T, Delta, FP4, Acros, E-6 slides, ECN-2 motion negatives …), 1 Pro/discontinued (Kodachrome 64, D-70, shut down 2009 — rendered as an approximation), 1 expansion profile marked COMING SOON. `filter_params` are calibrated against a real sample photo via the calibration grid (see docs/research.md for sources). Library counts live in the data files and are read from them, never restated here; the tier split is maintained by `scripts/patch-tiers.mjs`.
- `app.js` — `FilmEngine`: lens blur → luminance tone curve (contrast/black-lift/white-point) → chroma kept & scaled by saturation → split-tone tint blend → halation bloom → film grain → vignette → quirk overlays. The data files are the single source of truth; adding a camera or film = adding a JSON entry.
- **The viewfinder belongs to the body.** Each profile declares what its own finder really shows (`viewfinder` in `assets/cameras.json`: design id, optics, frame inset, parallax/close marks, the focusing aid it has and its shape, indicator lamps, and its readout — a needle on a scale or illuminated numerals, with the meter's own working aperture/shutter). `camera/viewfinder.js` draws exactly those marks; `scripts/patch-viewfinders.mjs` keeps the designs from manuals and refuses any mark no source states. Selecting a body in the bag switches its finder with it, and the two stay synchronised. A bare window draws nothing, an Albada finder draws its bright frame, a Galilean whose window *is* the field draws the viewfield edge, a rangefinder draws projected framelines plus a coincident patch, a waist-level body draws a ground screen; complexity follows the machine, and nothing is added to make a finder look sophisticated. Marks sit on the displayed picture (never on the letterbox bars), scale with the body's frame shape, never move the layout, and never reach the captured photograph. See *Camera-specific viewfinder system* in `docs/architecture.md` for the per-body research sources.
- Behavior that differentiates from typical film apps: the **roll state follows the film, not the camera** (swapping cameras never resets the 36-frame roll), correct 36-frame counting, rewind ritual.

## Archive & persistence (Round⑨)
- The Film Archive is a **darkroom record**, not a photo dump: every developed roll keeps camera/film/ISO/date-loaded/date-developed/status + **Roll Notes** ("Weekend in Toronto — Autumn 2026").
- Frames persist in **IndexedDB** across refresh, close, and offline; the archive exports/restores as a JSON backup file, and each roll exports as a `.zip` (full-res frames + roll.json). Export quality is q0.95 at native stream resolution — never silently downscaled. A backup carries the roll **currently in the camera** too, so someone who has only an undeveloped roll can still export it; a restore validates every record (including that one) before anything is written, commits the whole restore in **one** IndexedDB transaction across both stores, applies it to the UI only after the store agrees, and leaves the database and the camera untouched if the write fails — a partial restore is not possible. Image URLs coming from a backup file are validated against the formats this app writes and placed through real elements, never interpolated into HTML.
- Archive browsing is split: **BY ROLLS** (records, notes, contact sheet, batch download) vs **ALL FRAMES** (quick browse, ★ favorites filter, single-frame download with EXIF-like capture info).
- Every camera body renders differently on the same film: per-body sharpness, vignette, and flash behaviour profiles (`camera_character` in `assets/cameras.json`; verified by `test/camera-diff.mjs`). Lens distortion ships at **0 for every body today** — the plastic fisheye bulge warped straight lines, so the viewfinder stays rectilinear; the barrel map in the engine is kept for a future wide-angle pack.
- Settings carries the real purchase block: **GET PRO** opens the Payhip product, and a code entered there unlocks this browser (verified online, kept offline, refunded codes lock again). Nothing else in the app ever checks a purchase.

A native wrapper (Capacitor/TWA) can reuse the same engine and the same Payhip code later — it is not needed for selling today.
